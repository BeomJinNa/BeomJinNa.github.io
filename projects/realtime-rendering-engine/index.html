Architecture

렌더링 구조

에셋 변환과 로딩

파일 포맷이 달라도 렌더링에서는 같은 형식의 데이터를 사용할 수 있도록 모델·텍스처를 엔진 공통 형식으로 변환해 저장했습니다. 실행 중에는 변환된 데이터를 불러오도록 분리해, 렌더링 코드가 원본 파일 포맷이나 파서에 직접 의존하지 않게 했습니다.

장면 오브젝트 관리

여러 오브젝트가 공유하는 모델 구성과, 각 오브젝트의 위치·회전·애니메이션 상태를 분리해 관리했습니다. 매 프레임 렌더링에 필요한 데이터를 모아 전달하도록 구성해, 장면 상태를 관리하는 부분과 그리기 작업을 분리했습니다.

셰이더 자원 바인딩

Vulkan으로 확장할 때도 같은 HLSL 소스를 사용할 수 있도록, 셰이더에 텍스처·버퍼를 연결하는 번호 규칙을 정했습니다. DX12는 자원 종류가 다르면 같은 레지스터 번호를 쓸 수 있지만, Vulkan의 같은 descriptor set 안에서는 바인딩 번호가 겹치면 안 됩니다. 이에 맞춰 공통 인터페이스에서도 같은 그룹 안의 번호를 자원 종류와 관계없이 중복 없이 배정했습니다.

한 프레임의 렌더링 경로

GPU 자원 회수

CPU에서 해제를 요청해도 GPU는 해당 자원을 사용 중일 수 있습니다. 기존 핸들은 즉시 무효화해 새 작업에서 참조하지 못하게 하고, 실제 GPU 객체는 fence로 해당 자원을 사용한 작업의 완료를 확인한 뒤 해제합니다.

Animation

애니메이션 전환과 스키닝

정지·걷기·달리기(Idle·Walk·Run) 동작이 전환될 때 두 애니메이션의 포즈를 섞어 자연스럽게 이어지도록 했습니다. 행렬 자체를 보간하는 대신, 각 노드의 로컬 위치·크기는 선형 보간하고 회전은 quaternion slerp로 블렌딩했습니다.

보간한 로컬 변환은 루트부터 자식 순서로 누적해 각 관절의 장면 좌표계 변환을 구합니다. 이후 관절 변환을 메시의 로컬 좌표계로 옮기고 inverse bind matrix와 조합해, 정점을 현재 포즈로 변형하는 스키닝 행렬을 구성했습니다.

binned-SAH BVH visualization

04 · Visibility
